## Feito

### Investigação (antes de qualquer correção)
- Lida a imagem do erro de CI (GitHub Actions: `[ERR_PNPM_OUTDATED_LOCKFILE]` apontando `packages/crdt/package.json`) e o console log do `db:migrate` local.
- Verificado o mount do Projeto (`_MANIFEST.md`, gerado 2026-06-30) — confirmado que `packages/crdt/` (com `package.json`, `tsconfig.json`, `eslint.config.mjs`, `src/index.ts`) **ainda existe no disco real do usuário**, apesar de a DEC-011 (sessão 2026-06-26) ter decidido removê-lo. A remoção só foi aplicada no zip entregue naquela sessão — extrair um zip por cima de uma pasta existente não deleta o que não está no zip novo.
- Confirmado via `package__crdt.json` real: dependências `@automerge/automerge@^3.2.6` e `typescript@^6.0.3` — batem exatamente com "2 dependencies were added" do log de erro do CI.

- Reproduzido o erro do CI: `pnpm ls -r --depth -1` no sandbox reconstruído mostrou exatamente "6 workspace projects" (root + api + web + db + ui + **crdt**) — mesma contagem do console do usuário.
- Pesquisado o erro do `db:migrate`: confirmado bug conhecido e não corrigido nas versões estáveis 0.x do drizzle-kit/drizzle-orm (issues #5521, #5601, #5816, #5520 do repositório oficial `drizzle-team/drizzle-orm`) — a CLI engole o erro real de qualquer falha de migration e só imprime "Exit status 1". As versões citadas nas issues como afetadas (`drizzle-kit@0.31.10` + `drizzle-orm@0.45.2`) são EXATAMENTE as deste projeto.
- Reproduzido o bug do drizzle-kit no sandbox: criada uma migration com SQL inválido (referência a tabela inexistente), registrada manualmente no journal, `drizzle-kit migrate` rodou e terminou com exit code 1 e **zero linhas de erro** — confirmação direta, não só as issues do GitHub.

### Correção 1 — CI (packages/crdt)
- `packages/crdt/` deletado de fato do sandbox reconstruído.
- `pnpm install` (sem frozen) rodado para regenerar o lockfile sem as entradas do crdt — confirmado "5 workspace projects" depois.
- `pnpm install --frozen-lockfile` (o EXATO comando que o CI roda) executado com sucesso no sandbox — confirma que a correção resolve a falha real do CI.
- `pnpm typecheck`/`pnpm lint` revalidados nos 4 workspaces reais — limpos, sem regressão.

### Correção 2 — db:migrate silencioso
- Criado `packages/db/src/migrate.ts`: script que usa `migrate()` de `drizzle-orm/node-postgres/migrator` (API programática, documentada pelo próprio Drizzle como alternativa) num `try/catch` que imprime o erro real.
- `packages/db/package.json`: script `db:migrate` trocado de `drizzle-kit migrate` para `tsx src/migrate.ts`. `db:generate` e `db:studio` mantidos na CLI (só `migrate` tem o bug, já que é o único que fala com o banco de fato).
- `tsx` adicionado como devDependency de `packages/db`.
- Validado nos 4 cenários possíveis, contra um Postgres real instalado no sandbox: (1) SQL inválido → mostra `error: relation "tabela_inexistente" does not exist`; (2) senha errada → mostra `password authentication failed for user "postgres"`; (3) `DATABASE_URL` ausente → mensagem própria, sem tentar conectar; (4) caso feliz → aplica com sucesso e é idempotente ao rodar de novo (não reaplica, não falha).
